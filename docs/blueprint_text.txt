WEBSITE RISK & COMPLIANCE AUDIT Minimum Marketable Product — Product, Technical & Coding-Agent Blueprint Version 1.0  |  5 November 2026  |  Product implementation source of truth Preferred experience stack: Next.js + Vercel + Tailwind CSS, with Neon Postgres, Drizzle, Vercel Blob, Upstash, Razorpay and Resend. Browser execution is isolated behind a provider adapter: begin with a bounded Vercel-compatible runner only if current platform limits support it; move to a dedicated worker/hosted browser when reliability thresholds are breached. Purpose of this blueprint This document is the build specification for a URL-first Website Risk & Launch Readiness SaaS. It is written so a coding agent can implement the application in small, verifiable increments without inventing architecture, expanding scope, or turning every check into an LLM call. The agreed strategy is capture once, snapshot many: a controlled browser worker captures observable website evidence once; deterministic detectors evaluate that evidence; a versioned rules engine decides applicability and result status; selected paid-report text checks may use a small LLM with quote verification. Non-negotiable product decisions TypeScript end-to-end modular monolith; Next.js application deployed on Vercel; Tailwind CSS for UI. Browser execution is isolated behind getBrowser()/ScanRunner. Initial deployment may use playwright-core + @sparticuz/chromium in a Vercel route handler with a bounded maxDuration, provided current Vercel limits and memory are verified. Keep a clean fallback to Browserbase/Browserless or a small Docker worker on Railway/Fly.io. Never let detector code depend on the browser hosting choice. Neon PostgreSQL with Drizzle is the primary database. Use Upstash Redis for per-IP/per-domain rate limits and a small concurrency semaphore. For the first serverless execution model, use persisted scan states/events and a deadline-aware runner; do not add pg-boss unless a dedicated worker is adopted. If a worker is adopted, pg-boss on Postgres is the lean queue option. Capture evidence once, store it separately from check results, then run multiple detectors over the same snapshot. Four statuses only: Passed, Issue found, Not applicable, Unable to verify. Free scans are passive and use no LLM. DNS TXT or meta-tag ownership verification unlocks carefully scoped active probes. AI is restricted to five judgement-heavy checks: A8, E6, F5, F6, G4. Use batched calls, caching and verbatim quote verification. No AI-generated remediation in MMP. Use versioned, reviewed fix templates. No Lighthouse in MMP. Use browser timing and selected performance observations; do not market these as a Lighthouse score. Financial exposure is shown only when a defensible, source-backed model exists. Never sum overlapping statutory maximums. At launch market only the checks that have passed tests. Wave 1 target: approximately 41 checks, marketed as 40+. 1. Product definition and MMP scope 1.1 Product promise Scan a website before launch or client handover. Identify observable privacy, cookie, accessibility, security, legal-transparency, commercial, IP-risk and quality issues; show where each was found; explain what was actually tested; and provide practical fixes. 1.2 Primary users User Job to be done MMP experience Indie / vibe-coded SaaS founder Find launch-blocking website risks without needing a security or compliance team. Enter URL → passive scan → preview → pay to unlock complete evidence-backed report. Small web agency / freelancer Run a repeatable quality and risk check before client handover. Run a scan for a client site; export a professional report; share findings and outstanding items. 1.3 Explicit MMP exclusions Not a law firm, legal opinion, compliance certification, penetration-test certificate or guarantee of compliance. Not a full vulnerability assessment, authenticated penetration test or backend/database audit. Not automatic legal-policy generation or automatic production remediation. No repository/GitHub scan in MMP (G3 later). No authenticated password-reset or cross-account access tests in MMP (D14/D15 later). No paid reverse-image or copied-content search APIs in MMP (G5/G8 later). No agency workspace, white-label portal or team permissions in MMP. No exhaustive crawl: enforce a bounded page count and scan duration. 1.4 User journey Visitor enters a public website URL and confirms they are authorised to request a passive scan, and accepts the scanner terms. Application validates and normalises the URL, applies rate limits and creates a scan record. Next.js API validates the URL, applies Upstash limits, creates a scan row in Neon and starts the bounded runner (or enqueues to the worker fallback). It returns a scan ID immediately. ScanRunner performs passive capture, creates the shared snapshot and runs eligible detectors. It may execute in the Vercel-compatible runner, hosted browser or dedicated worker according to the configured provider. Free results show a limited set of high-confidence findings and summary counts. No hidden paid findings are returned by the API. User may verify domain ownership through a DNS TXT record or HTML meta tag to unlock scoped active probes. Payment unlocks the complete report and any paid-only AI analysis. The server rechecks entitlement on every report request. User can download a PDF and rerun a scan. Rescans preserve history and scanner/rule versions. 2. Capture engine specification 4.1 URL guard and SSRF protection Accept only http/https URLs; normalise host, remove fragments, reject credentials in URL and malformed ports. Resolve A and AAAA records before connection; reject loopback, private, link-local, multicast, reserved and cloud metadata ranges. Revalidate DNS resolution on every redirect and immediately before connection to reduce DNS-rebinding risk. Limit redirects (for example, 5), response bytes, download time, page count, total requests and total scan duration. Block requests to localhost, private networks, metadata endpoints and non-public IP ranges at the worker network layer as well as in code. Allow only expected protocols and ports; deny file:, ftp:, data: navigation and arbitrary local file access. Do not follow links to a different registrable domain in the default crawl. Record external links but do not crawl them. Use a transparent scanner User-Agent with contact/purpose URL. Respect robots.txt for crawling; robots.txt is not authorisation and does not replace the user's permission acknowledgement. Use isolated browser contexts and containers; no host filesystem mounts, no production credentials, no shared customer sessions. 4.2 Page discovery Start with the submitted URL, canonical redirect, robots.txt, sitemap.xml and same-origin navigation/footer links. Prioritise homepage, privacy, terms, cookies, contact, pricing, refund, login/signup and checkout pages when discovered. Limit Wave 1 crawl to 12–15 pages. Deduplicate canonical URLs and query variants; do not crawl infinite calendars, search results or parameter combinations. 4.3 Browser capture Use Playwright Chromium in a fresh isolated context per scenario. Capture final URL, status, title, meta description, language, viewport, DOM snapshot or selected DOM facts, screenshot and console errors. Record request/response URL, method, resource type, status, initiator where available, headers needed for checks and timing. Capture cookies and local storage metadata, but redact values that could contain session identifiers. Do not submit real forms in passive mode. Do not click destructive actions, purchase buttons or account actions. Set deterministic viewport and timeout settings; retry transient navigation failures once, not indefinitely. Use page-level and scan-level budgets; stop cleanly and mark missing evidence Unable to verify. 4.4 Consent experiment Run three independent fresh browser contexts to prevent state contamination: Run Actions Evidence No choice Navigate; wait a bounded period; do not interact with banner. Requests, cookies, local storage and visible consent UI before any choice. Accept Fresh context; locate and activate the visible Accept/Allow-all control once. Requests and storage after acceptance; button text/selector and screenshot. Reject Fresh context; locate Reject/Decline/Essential-only control; activate once. Requests and storage after rejection; button text/selector and screenshot. Do not assume button labels. Use conservative selector/text matching and record whether the action was confidently identified. Do not treat failure to find a Reject button as proof it does not exist; use Unable to verify if the UI is ambiguous. Compare known tracker requests/cookies across scenarios, with a maintained tracker-domain/category list. Do not declare a legal violation solely because a third-party request occurred. The rule layer applies jurisdiction, purpose and consent logic. Record experiment timestamp, locale, viewport, banner interaction and all collection warnings. 4.5 Snapshot and evidence Capture worker outputs observations, not legal conclusions. Each evidence record should include scan ID, page URL, observation type, timestamp, source locator, raw/normalised value, confidence where relevant, and storage pointer. Detectors consume evidence references and return structured results. 4.6 Resource limits Limit MMP target Behaviour on limit Pages 12–15 same-origin pages Stop discovery; mark unvisited page-dependent checks Unable to verify. Total scan time 60–90 second target, hard bounded timeout Finish with partial snapshot and collection warnings; do not silently pass checks. Worker concurrency One worker initially; one browser per worker slot Scale only after measuring memory and queue latency. Memory Budget approximately 1 GB per concurrent browser as planning assumption Kill/recycle worker on memory threshold; preserve failure reason. Downloads Strict per-file and total bytes cap Skip oversized files and record warning. Redirects Maximum 5 Stop and mark destination check unable to verify. Retries One bounded retry for transient network failures Avoid retry storms. 5. AI policy and cost controls 6.1 AI scope Tier Checks / purpose MMP treatment Tier 0 — deterministic 51 checks: browser, network, DOM, regex, DNS, headers, known tracker/CVE lists No LLM. Free scan can use these. Tier 1 — rules/keywords 14 checks: A2, A3, A4, A5, A7, A9, C8, E3, E7, F1–F4, G7 Keyword/rule extraction first. No LLM required for MMP; AI refinement is optional future work. Tier 2 — AI judgement A8, E6, F5, F6, G4 Paid report only; batched calls, small model, source quotes verified against captured text. Tier 3 — external paid APIs G5 and G8 Defer. Use external search/image matching only after validating willingness to pay and per-report economics. Tier 4 — access dependent D14, D15 and G3 Defer to authenticated/repository product tier. 6.2 AI workflow Run deterministic extraction first; identify only relevant policy, terms, pricing, claim and testimonial text. Do not send full HTML, screenshots, cookies, session tokens, credentials or raw customer-submitted PII. Run AI only after payment and only when source material exists and the relevant check is applicable. Batch by document: one privacy-policy call can answer A8-related scope questions where relevant; one commercial-text call can cover relevant claims. Keep a strict prompt/output schema. Require each conclusion to include a verbatim quote and source URL/offset. Verify the quote exists in the captured source; discard unsupported outputs. Cache by normalised content hash + prompt version + model ID. Reuse only if the source content and prompt version match. Store model ID, prompt version, token counts, estimated cost and quote-validation result. Use confidence thresholds only for routing to human review; do not convert model confidence into legal certainty. 6.3 AI output schema {   "checkId": "E6",   "finding": "possible_disclaimer_gap",   "sourceUrl": "https://example.com/advice",   "quotes": ["Exact text copied from captured page"],   "reason": "Why this text triggered the check",   "confidence": 0.78,   "needsHumanReview": true } Quote verification is mandatory: every returned quote must be an exact substring of the source text after only safe whitespace normalisation. No quote means no finding. AI output is an observation for the rules engine, not the final legal decision. 6.4 Cost controls No AI in free scan. Maximum 3–4 small-model calls per paid report as an initial budget target, not a guaranteed cost. Per-document batching; skip missing documents and irrelevant checks. Content-hash caching; cache key includes model and prompt version. Input truncation by relevance, output token cap and request timeout. Security, privacy and operational controls Threat-model the scanner as an internet-facing service that processes hostile content. If using a dedicated worker, run it as non-root in a container with seccomp/AppArmor or equivalent hardening where supported. For Vercel/hosted-browser modes, enforce equivalent isolation, short-lived credentials and strict network egress controls. No access to cloud metadata, internal networks, host filesystem, Docker socket or production secrets from browser context. Separate app credentials from scan-runner credentials; runner gets only job-specific, short-lived access. Use outbound network controls and DNS/IP validation at connection time; block private/reserved destinations. Limit request methods, concurrency, response sizes, redirects, pages and total time. Redact PII and secrets from evidence; never send them to LLM. Encrypt database and object storage; use least-privilege roles and short-lived signed URLs. Keep audit logs for ownership verification, active scans, payments and report access. Provide scan cancellation and global active-probe kill switch. Use dependency scanning, secret scanning, lockfile review and routine patching. 14.1 Legal and claims guardrails Use language such as 'potential issue', 'observed risk', 'could require review' and 'unable to verify'. Do not claim 'compliant', 'certified', 'legally safe' or 'guaranteed protection'. Legal rule records need jurisdiction, source, version, effective date and last reviewed date. Do not treat WCAG as a universal law for every website; distinguish standard findings from legal applicability. Do not claim an image is stolen, an endorsement is fake or a statement is false based only on automated similarity/pattern signals. Have qualified legal/security reviewers validate high-stakes rule mappings before commercial use. 15.
